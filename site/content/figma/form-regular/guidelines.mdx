# Guidelines

Design and implementation principles for creating effective, accessible, and consistent form experiences. These guidelines ensure form components serve their functional purpose while maintaining visual harmony and usability standards across all interface contexts.

## Accessibility Considerations

Accessibility standards and inclusive design practices that ensure form components remain usable for all users regardless of their abilities or interaction methods.

### Color Contrast

Ensure sufficient contrast between form text, labels, and background colors to meet WCAG accessibility standards. Form variants must maintain readable contrast ratios across all states, including error and success feedback.

### Focus States

Provide distinct visual indicators for keyboard navigation and screen reader users. Focus states should be clearly visible and consistent across all form variants without compromising the overall design aesthetic.

### Label Association

Include proper label association and semantic markup for all form inputs. Clear labeling ensures assistive technologies can properly communicate field purpose, requirements, and validation status.

## Design Principles

Core design principles that guide form implementation decisions, ensuring consistency, clarity, and optimal user experience across all interface contexts.

### Visual Hierarchy

Establish clear importance levels through appropriate form field grouping and sizing. Required fields should be clearly indicated, while optional fields maintain visual balance without competing for attention.

### Consistency

Apply form variants systematically throughout the interface. Similar input types should use the same visual treatment, creating predictable patterns that users can rely on for data entry and completion.

### Spacing and Proportions

Maintain consistent sizing, padding, and spacing relationships across all form implementations. Proper proportions ensure forms remain accessible and visually balanced across different screen sizes and contexts.

## Content Strategy

Guidelines for form labeling, messaging, and content hierarchy that enhance user understanding and successful form completion.

### Clear Field Labels

Write field labels that immediately communicate the required input type and format. Avoid ambiguous terms that leave users uncertain about what information to provide.

#### Do

Use specific, descriptive language that clearly indicates the expected input format.

#### Don't

Use generic labels that don't clearly indicate the field's purpose or requirements.

### Helpful Placeholder Text

Provide placeholder text that demonstrates proper input format without replacing clear labels. Use placeholders to show examples rather than essential instructions.

#### Do

Use placeholder text to show format examples while maintaining visible field labels.

#### Don't

Rely solely on placeholder text to communicate field requirements or purpose.

### Error and Success Messaging

Craft clear, actionable error messages that guide users toward successful completion. Success indicators should provide positive reinforcement without overwhelming the interface.

#### Do

Provide specific guidance on how to correct input errors with clear next steps.

#### Don't

Use generic error messages that don't help users understand how to fix issues.

## Visual Consistency

Standards for maintaining cohesive form appearance and behavior patterns across all interface contexts and user interactions.

### Design Token Usage

Apply standardized design tokens for all form styling properties. Consistent token usage ensures visual harmony and enables efficient theme customization across the entire design system.

#### Do

Use predefined design tokens for colors, typography, spacing, and sizing properties.

#### Don't

Create custom styling that deviates from established design token values.

### Field Grouping

Organize related form fields with logical spacing and visual grouping. Use consistent spacing patterns to create clear relationships between related inputs and sections.

#### Do

Group related fields together with consistent spacing and visual separation between sections.

#### Don't

Mix different spacing patterns within the same form or related field groups.

### Input State Consistency

Maintain consistent visual treatment across all input states including idle, focus, error, success, and disabled. State changes should be immediately recognizable while maintaining overall design harmony.

#### Do

Use consistent state indicators across all form input types and variants.

#### Don't

Apply different state styling patterns to similar form elements within the same interface.

## Form Layout Patterns

Best practices for form structure, field arrangement, and user flow that enhance completion rates and reduce cognitive load.

### Single Column Layout

Use single-column layouts for optimal form completion rates and mobile compatibility. Single columns create clear reading patterns and reduce form abandonment.

#### Do

Arrange form fields in a single column for better scanning and completion flow.

#### Don't

Use multi-column layouts unless specifically required for related field pairs.

### Progressive Disclosure

Break complex forms into logical steps or sections to reduce overwhelming users with too many fields at once. Use clear progress indicators for multi-step processes.

#### Do

Divide long forms into manageable sections with clear progress indication.

#### Don't

Present all form fields simultaneously when the form contains more than 7-10 inputs.

### Required Field Indication

Clearly distinguish required fields from optional ones using consistent visual indicators. Consider indicating optional fields rather than required ones when most fields are mandatory.

#### Do

Use consistent visual indicators to clearly distinguish required from optional fields.

#### Don't

Leave field requirements ambiguous or use inconsistent indication methods.

## Validation and Feedback

Standards for form validation, error handling, and user feedback that guide successful form completion and reduce user frustration.

### Real-time Validation

Provide immediate feedback for field validation when appropriate, especially for format requirements and availability checks. Balance helpfulness with avoiding premature error states.

#### Do

Validate fields after user completes input to provide immediate helpful feedback.

#### Don't

Show error states before users have had a chance to complete their input.

### Contextual Help

Offer contextual assistance and formatting guidance near relevant form fields. Help text should be easily discoverable without cluttering the interface.

#### Do

Provide contextual help text near fields that require specific formatting or guidance.

#### Don't

Hide essential formatting information in tooltips or separate help sections.

### Success Confirmation

Clearly communicate successful form submission and next steps. Provide confirmation that gives users confidence their information was received and processed.

#### Do

Show clear confirmation messages with details about what happens next.

#### Don't

Leave users uncertain about whether their form submission was successful.
