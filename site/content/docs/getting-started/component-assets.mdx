## Overview

Component assets are special Figma components that serve as the content layers for Chassis UI components. Instead of using plain text, icons, or images directly, Chassis components use swappable asset instances. This innovative approach allows you to modify component content and styling without detaching from the main component library, maintaining design system consistency while enabling flexibility.

## Why Component Assets?

### The Problem with Traditional Components

In traditional Figma component libraries, customizing content often requires either:

1. **Overriding text layers**: Limited to text changes only
2. **Detaching instances**: Breaks connection to the source component
3. **Creating variants**: Leads to exponential variant combinations

### The Asset Component Solution

Asset components solve these problems by making content layers swappable instances:

```
Button Component
├─ Background (shape)
├─ Text Asset Instance (swappable)
├─ Icon Asset Instance (swappable)
└─ State layers
```

**Benefits**:
- ✅ Swap content without detaching
- ✅ Maintain component updates from library
- ✅ Support complex state changes (e.g., loading skeletons)
- ✅ Enable consistent typography and iconography
- ✅ Reduce variant proliferation

## Asset Categories

### Text Assets

Text assets provide consistent typography and enable advanced text presentations.

#### Basic Text

Standard text components with predefined styles.

**Use cases**:
- Labels, headings, body copy
- Button text, form labels
- Menu items, list entries

**Features**:
- Auto-layout compatible
- Responds to text style tokens
- Supports text transformations

#### Stacked Text

Multi-line text components for hierarchical information.

**Use cases**:
- Card titles with subtitles
- List items with descriptions
- Form labels with helper text

**Features**:
- Title + subtitle/description layouts
- Consistent spacing between text elements
- Responsive to container width

#### Description List

Key-value pair text components for structured data.

**Use cases**:
- Property specifications
- Data tables and details views
- Settings and configurations

**Features**:
- Horizontal and vertical layouts
- Consistent label-value spacing
- Supports long-form values

### Background Assets

Background components provide consistent surface treatments and decorative elements.

#### Common Background

Standard background shapes and patterns.

**Use cases**:
- Card backgrounds
- Section dividers
- Surface elevation indicators

**Features**:
- Responds to surface tokens
- Supports border radius tokens
- Compatible with shadow tokens

#### Separator Background

Divider and rule components.

**Use cases**:
- Content section breaks
- List item dividers
- Navigation separators

**Features**:
- Horizontal and vertical orientations
- Thickness variants
- Color responsive to theme

#### Balloon Background

Speech bubble and callout backgrounds.

**Use cases**:
- Tooltips and popovers
- Chat messages
- Annotation callouts

**Features**:
- Multiple pointer directions
- Rounded corner variants
- Shadow and elevation support

### Icon Assets

Icon assets ensure consistent iconography across all components.

#### Basic Icons

Standard icon components from the Chassis icon library.

**Use cases**:
- Button icons
- Navigation icons
- Status indicators

**Features**:
- 478+ icon library
- Multiple size variants
- Color responsive to theme tokens

#### Stacked Icons

Composite icon arrangements for badges and notifications.

**Use cases**:
- Icons with notification badges
- Layered status indicators
- Icon + count combinations

**Features**:
- Pre-defined stacking patterns
- Badge positioning variants
- Maintains icon alignment

#### Glyphs

Special character and symbol components.

**Use cases**:
- Currency symbols
- Mathematical operators
- Custom UI symbols

**Features**:
- Consistent sizing with icons
- Theme-aware coloring
- Accessible labeling

### Skeletons

Skeleton assets provide loading state representations.

#### Shape Skeletons

Geometric placeholder shapes for loading states.

**Use cases**:
- Image placeholders
- Avatar loading states
- Card media skeletons

**Features**:
- Multiple geometric shapes
- Animated shimmer effects
- Responds to loading tokens

#### Text Skeletons

Line-based placeholders for text content.

**Use cases**:
- Paragraph loading states
- List item placeholders
- Form label skeletons

**Features**:
- Multiple line length variants
- Title + body combinations
- Animated loading effects

**Example - Button Loading State**:

```
Normal State:  [Icon] Button Text
Loading State: [Spinner] [Text Skeleton]
```

Swap text asset → text skeleton asset
Swap icon asset → spinner asset

### Spinners

Animated loading indicators.

#### Circle Spinner

Rotating circular loading indicator.

**Use cases**:
- Button loading states
- Page loading indicators
- Async operation feedback

**Features**:
- Multiple size variants
- Theme-aware colors
- Smooth rotation animation

#### Pulse Spinner

Pulsing dot loading indicator.

**Use cases**:
- Inline loading states
- Subtle progress indicators
- Chat typing indicators

**Features**:
- 1-3 dot variants
- Customizable pulse timing
- Compact footprint

### Switches

Toggle and switch control assets.

#### Basic Switch

Standard toggle switch component.

**Use cases**:
- Settings toggles
- Feature flags
- Binary choice controls

**Features**:
- On/off states
- Disabled state support
- Touch-friendly sizing

#### iOS Switch

Native iOS-style toggle switch.

**Use cases**:
- iOS app designs
- Platform-specific UIs
- Native feel requirements

**Features**:
- iOS design guidelines compliant
- Platform-accurate sizing
- Realistic animation timing

## Working with Assets

### Swapping Assets

1. Select component instance
2. Find asset layer in right panel properties
3. Click instance swap icon
4. Choose new asset from menu

### Best Practices

**Do**:
- ✅ Use assets for all content layers
- ✅ Maintain asset library organization
- ✅ Test asset swaps across themes
- ✅ Document custom asset usage

**Don't**:
- ❌ Detach assets to make changes
- ❌ Mix asset types incorrectly
- ❌ Create duplicate custom assets
- ❌ Override asset instance properties

### Custom Assets

When creating custom assets for your project:

1. **Follow naming conventions**: `Asset/Category/Name`
2. **Use auto-layout**: Enable responsive behavior
3. **Apply tokens**: Use variables for all styling
4. **Test thoroughly**: Verify across all themes and sizes
5. **Document usage**: Add descriptions and examples
